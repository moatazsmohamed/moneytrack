## Server foundation interfaces — worker A
Owned files: server/db.js, server/migrate.js, db/migrations/*.sql, server/security.js, server/auth.js, server/email.js, server/index.js, scripts/bootstrap-admin.js, tests/auth-unit.test.js. No auto bootstrap credentials on startup. All app tables prefixed mt_. DATABASE_URL only env, never print. MySQL pool TLS as required by DSN; exports pool, query(sql,params=[]) -> rows, transaction(fn) -> result where fn(conn) receives mysql2 connection. Schema migrations finite and close pool when standalone. Index imports default routers from ./workspace.js and ./admin.js (worker B). Export createApp() for integration, starts listener only if run directly. Default port 3000 on 0.0.0.0, honor PORT. GET /api/health actual DB readiness, no secret diagnostics. GET /api/public/config includes {emailConfigured:boolean,version:'2.0.0'}.

Security exports async requireAuth(req,res,next), requireReady(req,res,next) (must be verified, active, password changed), requirePermission(permission) -> middleware; csrfGuard(req,res,next); async recordAudit(actorId,action,targetId=null,metadata={},conn=pool); async checkRateLimit(key,limit,windowSeconds,conn=pool). Auth middleware sets req.auth={user,sessionHash,csrfToken}; user={id,email,fullName,role:'USER'|'ADMIN'|'SUPER_ADMIN',permissions:[],status:'active'|'suspended',emailVerified,mustChangePassword,createdAt}. Never serialize password/session hashes. User role/session/status from database each request, reject suspended old cookies immediately. requirePermission SUPER_ADMIN allowed except no self-delete or removing last superadmin; ADMIN uses assigned permission strings, cannot promote, modify SUPER_ADMIN, or read financial data. USER never administrative.

Errors HTTP JSON {error:{code,message}}. Codes stable English machine strings, frontend translates friendly generic fallbacks. Route success JSON as below. Auth/session cookies moneytrack_session and moneytrack_preauth, HttpOnly, SameSite=None, Secure for public HTTPS; local HTTP explicitly distinct config not NODE_ENV/req.secure based. CSRF derived from opaque cookie, returned via /auth/me or /auth/csrf; write requests header X-CSRF-Token. Don't use reserved platform cookie names. Valid Origin/CSRF, no wildcard credentialed CORS. API responses private,no-store. No X-Frame-Options/frame-ancestors blocking Preview.

Auth routes relative mount /api/auth:
GET /csrf -> {csrfToken}; GET /me -> {user:null|User,csrfToken,emailConfigured};
POST /register {fullName,email,password,confirmPassword,acceptTerms:true,language:'ar'|'en'} -> {verificationRequired:true}; fail EMAIL_UNAVAILABLE/EMAIL_DELIVERY_FAILED if SMTP unavailable (never pretend email sent). PUBLIC role always USER regardless extra role/permissions fields (reject or ignore securely).
POST /login {email,password,remember:boolean} -> {user,csrfToken}; allow temporary superadmin sign-in, but requireReady blocks domain/admin actions until password changed.
POST /logout -> {ok:true}; POST /forgot-password {email,language} -> generic {ok:true} only if service configured; POST /reset-password {token,password,confirmPassword} -> {ok:true}; POST /verify-email {token} -> {ok:true}; POST /resend-verification {email,language} -> {ok:true}; all token secrets stored SHA256 only, expire and one-time.
PATCH /profile {fullName} -> {user}; POST /change-password {currentPassword,newPassword,confirmPassword} -> {user,csrfToken} with new rotated session and mustChangePassword=false; POST /change-email {email,currentPassword,language} -> {verificationRequired:true} then confirmation uses /verify-email; DELETE /account {currentPassword,confirm:'DELETE'} -> {ok:true}, protected CSRF/current-password, no deleting last SUPER_ADMIN or self via admin API.
Bootstrap CLI reads MONEYTRACK_ADMIN_EMAIL / MONEYTRACK_ADMIN_PASSWORD env or secure interactive input; initial user SUPER_ADMIN active/verified controlled setup, must_change_password=1. Must not reset existing account or print credentials. Initial weak numeric password allowed ONLY bootstrap temporary exemption; normal passwords >=12, reject numeric-only/obvious short. scrypt salt + safe params, timing safe verify.

## Schema (worker A must implement exact shared columns)
Use UUID CHAR(36) with Unicode-compatible utf8mb4 text, timestamps created_at/updated_at DATETIME(6), FK/cascades. API privately owns all SQL; clients no DB access. Schema designed to avoid reserved words by field names below.
mt_profiles: id PK,email varchar254 unique,password_hash varchar255,full_name varchar100,status enum(active,suspended),email_verified boolean,must_change_password boolean,session_version int default0,last_login_at nullable DATETIME6,created_at,updated_at.
mt_user_roles: user_id PK FK profiles,role enum(USER,ADMIN,SUPER_ADMIN),permissions_json JSON(default via insert []),created_at,updated_at.
mt_sessions: token_hash CHAR64 PK,user_id FK profiles,session_version int,expires_at DATETIME6,created_at,updated_at.
mt_email_tokens: id UUID PK,user_id FK profiles,token_hash CHAR64 unique,purpose enum(verify_email,reset_password,change_email),payload_json JSON nullable,expires_at DATETIME6,consumed_at nullable,created_at,updated_at.
mt_user_settings: user_id PK FK profiles,prefs_json JSON,notification_prefs_json JSON,revision BIGINT default0,created_at,updated_at. prefs existing shape {theme,language,currency,name}; notification prefs {budget:true,recurring:true,goals:true,security:true}.
mt_categories: id UUID PK,user_id FK,name_en varchar120,name_ar varchar120,category_type enum(income,expense),icon varchar80,color CHAR7,created_at,updated_at; UNIQUE(user_id,id) for ownership FK.
mt_transactions: id UUID PK,user_id FK,category_id UUID,title varchar240,amount DECIMAL(16,2),transaction_type enum(income,expense),transaction_date DATE,description TEXT,is_demo boolean default0,created_at,updated_at; composite FK(user_id,category_id)->categories(user_id,id), index(user_id,transaction_date), amount constraints.
mt_budgets: id UUID PK,user_id FK,month_key CHAR7,scope_key varchar36 ('total' or category UUID),category_id nullable UUID,amount DECIMAL16,2,created_at,updated_at; UNIQUE(user_id,month_key,scope_key), composite category ownership FK. Return legacy budgets object {YYYY-MM:{total,categories:{catId:amount}}}.
mt_savings_goals: id UUID PK,user_id FK,title varchar120,target_amount DECIMAL16,2,target_date nullable DATE,created_at,updated_at; UNIQUE(user_id,id).
mt_goal_contributions: id UUID PK,user_id FK,goal_id UUID,amount DECIMAL16,2,contribution_date DATE,note varchar240,created_at,updated_at; composite goal ownership FK, cascade.
mt_recurring_transactions: id UUID PK,user_id FK,title varchar240,amount DECIMAL16,2,transaction_type enum(income,expense),category_id UUID,frequency enum(weekly,monthly,yearly),start_date DATE,next_due_date DATE,end_date nullable DATE,is_active boolean,description TEXT,created_at,updated_at; composite category ownership FK.
mt_recurring_occurrences: id UUID PK,user_id FK,recurring_id UUID,due_date DATE,transaction_id UUID,created_at,updated_at; UNIQUE(recurring_id,due_date). Retain occurrences on editing rule, never recreate processed date.
mt_notifications: id UUID PK,user_id FK,notification_type varchar40,title_key varchar80,body_json JSON,is_read bool,dedupe_key varchar120 nullable,created_at,updated_at; UNIQUE(user_id,dedupe_key).
mt_activity_logs: id UUID PK,actor_id nullable UUID (ON DELETE SET NULL),action varchar80,target_id nullable UUID,metadata_json JSON,created_at,updated_at. Don't put financial amounts/titles or tokens/passwords in metadata. B handles per-user audit metadata only entity type/count. A handles security events.
mt_imports: id UUID PK,user_id FK,fingerprint CHAR64,record_count INT,created_at,updated_at; UNIQUE(user_id,fingerprint).
mt_platform_content: id UUID PK,content_type enum(faq,announcement,settings),content_key varchar120 unique,data_json JSON,is_published bool,created_at,updated_at. FAQ data={question:{en,ar},answer:{en,ar},order:number}; announcement data={title:{en,ar},body:{en,ar}}; settings key='platform-settings' data={supportEmail:'',platformName:'MoneyTrack',tagline:{en,ar},...safe preferences}. Don't store backend secrets here. Settings published public projection whitelist only.
mt_contact_messages: id UUID PK,name varchar100,email varchar254,message TEXT,status enum(new,read),created_at,updated_at.
mt_rate_limits: key_hash CHAR64 PK,hits INT,window_start DATETIME6,updated_at DATETIME6. mt_schema_migrations: migration_key PK,applied_at.
