# MoneyTrack — المرحلة الرابعة 2.0.0

منصة مالية شخصية بواجهة HTML5/CSS3/Vanilla JavaScript وChart.js وLucide، وخادم Node.js/Express وقاعدة MySQL متوافقة. العربية والإنجليزية وRTL/LTR والمظهران وEGP افتراضياً. لا React أو Supabase أو اتصال بحساب بنكي. أُعيد استخدام وحدات المعاملات والفئات والميزانيات والتقارير السابقة، مع حسابات سحابية منفصلة وواجهة عامة ولوحة إدارة وأهداف ادخار وقواعد دورية وإشعارات.

## الحالة المهمة قبل الاستخدام

**البريد غير مُعد في نشر هذه المرحلة، باختيار المالك.** لا تعمل عمليات التسجيل العام التي تحتاج التحقق بالبريد، وإرسال استعادة كلمة المرور أو تغيير البريد، حتى ضبط SMTP. يعرض الخادم والواجهة حالة عدم توفر الخدمة ولا يدعيان إرسال رسالة. الدخول إلى الحسابات الموجودة وتغيير كلمة المرور مع معرفة الحالية يعملان. اختبارات التحقق والاستعادة تستخدم SMTP محلياً اختبارياً؛ ليست دليلاً على تسليم بريد في الإنتاج.

**Cron الخارجي غير مُعد.** يُنفّذ catch-up للقواعد المستحقة عند فتح مساحة الحساب، بشكل ذري ودون ازدواجية. لتوليد السجلات عندما يكون المستخدم غير متصل، يلزم إعداد جدولة خادمية آمنة كما في `docs/SETUP.md`. السجلات الدورية ليست مدفوعات بنكية.

## التشغيل المحلي

يلزم Node.js 22.23.4 أو أحدث وpnpm 11.25.0 وقاعدة MySQL متوافقة تعمل عبر اتصال خادمي آمن. مكتبات الواجهة مرفقة، لكن نسخة الحسابات لا تعمل بخادم ملفات Python أو GitHub Pages وحده.

```bash
npm install -g pnpm@11.25.0
pnpm install --frozen-lockfile
cp .env.example .env
# ضع DATABASE_URL الفعلي في .env دون رفعه إلى Git
pnpm migrate
pnpm build
pnpm dev
```

افتح `http://127.0.0.1:3000`. للتطوير عبر HTTP محلي فقط ضع `MONEYTRACK_LOCAL_HTTP=true`. لا تستخدم هذا الخيار في الإنتاج؛ HTTPS يستخدم cookies آمنة HttpOnly/Secure/SameSite=None. قاعدة التطوير المُدارة في مشروع Manus مشتركة مع الإنتاج؛ لا تُجرِ اختبارات مدمرة على حسابات حقيقية.

## إعداد المالك

`pnpm bootstrap:admin` ينشئ SUPER_ADMIN مرة واحدة باستخدام متغيرات بيئة سرية. لا يُدخل الدور في نموذج التسجيل، ولا يضع كلمة المرور في المصدر، ولا يعيد ضبط الحساب الموجود. يفرض تغيير كلمة المرور المؤقتة عند أول دخول، ثم تُحذف متغيرات التهيئة. راجع `docs/SETUP.md`. بيانات دخول المالك لا توجد في هذا الملف أو الواجهة.

## البيانات والخصوصية

البيانات المالية والنسخ الاسترجاعية محفوظة في قاعدة البيانات ومقيدة بالمستخدم الموثق. لا تُحفظ جلسات أو tokens أو معاملات الحساب في LocalStorage. تُستخدم تفضيلات عرض عامة وحالة تنبيه تبديل الحساب فقط في المتصفح. يظهر خيار ترحيل بيانات النسخة المحلية القديمة بمراجعة ونسخة احتياطية وموافقة، دون حذفها صامتاً أو استيرادها تلقائياً إلى أي حساب.

صادرات JSON/CSV خاصة بحساب المستخدم. الاستعادة تتطلب تأكيد الاستبدال وتحفظ نسخة استرجاعية خادمية؛ الحد 2 MiB UTF-8. CSV يحمي الخلايا النصية من صيغ الجداول. تغيير عملة العرض لا يحوّل قيم الأموال. لا ترفع نسخك المالية إلى GitHub. بيانات المعاينة العامة توضيحية وموسومة، ولا تُضاف تلقائياً لحساب فعلي.

لوحة الإدارة تعرض المستخدمين والحالات والنمو والمحتوى والتواصل وحالة الخدمات، لا معاملات المستخدمين الفردية. الأدوار والحالة تُفحص خادمياً لكل طلب. تعليق الحساب يلغي قدرته على استخدام الجلسة القديمة. أي حساب جديد من التسجيل يحصل على USER فقط.

## البنية

- `index.html` و`public/`: الصفحة العامة وصفحات الحساب والسياسات والإدارة.
- `app.html` و`js/app.js`: مساحة المستخدم المحمية والتنقل الحالي.
- `js/storage.js` و`api-client.js` و`auth.js`: حالة الحساب والبيانات السحابية وCSRF دون tokens محلية.
- `js/legacy-storage.js` و`migration.js`: التحقق من النسخة القديمة والترحيل الصريح.
- `js/transactions.js`, `categories.js`, `budgets.js`, `reports.js`, `dashboard.js`, `charts.js`: الوحدات المالية المحفوظة.
- `js/goals.js`, `recurring.js`, `notifications.js`: امتدادات المرحلة الرابعة.
- `server/`: الهوية والجلسات والتفويض والبريد وواجهات البيانات والإدارة.
- `db/migrations/`: SQL منظّم قابل للتطبيق بالتتابع.
- `scripts/build.js`: بناء ملفات الواجهة، و`Dockerfile`: نشر الخادم.
- `scripts/build-vercel.js` و`vercel.json`: واجهة proxy إلى أصل الخادم؛ لا تنشر HTML الإدارة خارج حارس الجلسة.
- `docs/SETUP.md` و`docs/SECURITY_SOURCES.md`: الإعداد ومراجع قرارات الأمان.
- `tests/`: اختبارات الوحدات والتكامل. `TESTED_FEATURES.md`: سجل نتائج حقيقية.

## النشر

الخادم وقاعدة البيانات على الاستضافة المُدارة، وVercel يعيد توجيه طلبات الموقع إلى أصل الخادم الدائم عبر HTTPS. الخادم يخدم الصفحات والأصول ويمنع فتح `/app` و`/admin` دون جلسة مناسبة. لا تُنسخ بيانات قاعدة البيانات أو SMTP أو بيانات التهيئة إلى Vercel أو ملفات JavaScript. لا تستبدل الأصل الدائم بعنوان معاينة أو localhost.

الحاوية تثبّت الاعتمادات بالـlockfile وتبني الملفات أثناء البناء، ثم تقرأ `DATABASE_URL` عند التشغيل. `/api/health` فحص جاهزية دون بيانات حساسة. طبّق SQL قبل النشر؛ البناء لا يتصل بقاعدة البيانات. لا تعتمد نسخة الحسابات على النشر الثابت وحده.

## الاختبارات

```bash
node --test tests/*.test.js
node --test --test-concurrency=1 tests/integration/security.test.js
```

اختبار التكامل ينشئ حسابات مؤقتة ببادئة اختبارية، يستخدم SMTP محلياً مخصصاً، ثم يحذف حساباته وبياناته فقط. لا ينفّذ على بياناتك المالية الحقيقية. يغطي العزل بين حسابين، منع رفع الدور، حجب الإدارة عن USER، التعليق، البريد ذي الرمز أحادي الاستخدام، حذف الحساب بعلاقاته، وأهداف/دورية/تنبيهات المالك.
