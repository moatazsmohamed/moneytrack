# مصادر وقرارات تخزين كلمات المرور

تستخدم المرحلة الرابعة scrypt المدمجة في Node.js بمعاملات N=2^17 وr=8 وp=1، وsalt عشوائي 16 بايت ومقارنة ثابتة الوقت. استُخدمت توصية OWASP الحالية عند التحقق بتاريخ 14 نوفمبر 2026. تُقيد عمليات الاشتقاق إلى عملية واحدة في المثيل وطابور محدود، حتى لا يؤدي عامل الذاكرة إلى استنزاف الخادم تحت الطلبات المتزامنة.[1]

مسودة IETF رقم 09 من أبريل 2026 توافق القيم نفسها وتؤكد ملاءمة عامل العمل للتطبيق. هذه مسودة انتهى تاريخ صلاحيتها في أكتوبر 2026 وليست معياراً نهائياً؛ الاستناد التنفيذي هنا إلى OWASP، ولا ندعي اعتماداً أو شهادة أمنية.[2]

تبقى تجزئات الجلسات وتوكنات البريد SHA-256 لأنها أسرار عشوائية قوية، ولا يُستعمل SHA-256 وحده لتخزين كلمات المرور. كلمات المرور الأولية لا تدخل المصدر أو SQL أو السجلات، بل إعداد خادمي مؤقت ثم تجزئة في قاعدة البيانات. لا تُفعل هوية وهمية في التطوير. تحتاج توصيات الأمان إلى مراجعة مستمرة عند تغير مكتبات التشغيل أو متطلبات الحمل.
