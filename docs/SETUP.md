# إعداد المرحلة الرابعة

## قاعدة البيانات والتشغيل

يوضع `DATABASE_URL` فقط في البيئة الخادمية/مدير الأسرار. مثال البنية: `mysql://USER:PASSWORD@HOST:PORT/DATABASE`؛ المثال ليس اتصالاً صالحاً ولا يحتوي اعتماداً. حساب التطبيق يحتاج صلاحيات جداول MoneyTrack فقط. لا تضع المتغير في `VITE_` أو `PUBLIC_` أو واجهة المتصفح. الخادم يستخدم mysql2 واستعلامات محددة المعاملات وعزل `user_id`، ولا يوفر SQL API عاماً.

```bash
pnpm install --frozen-lockfile
pnpm migrate
pnpm build
pnpm start
```

المهاجرات محفوظة في `db/migrations/` وتُسجل في `mt_schema_migrations`. تشمل الإشعارات المخفية والنسخة الاسترجاعية المقيدة بالحساب. الترحيلات ليست rollback للبيانات؛ احتفظ بنسخة قاعدة قبل تغييرات بنيوية مستقبلية. هذه المرحلة طُبقت على قاعدة المشروع المُدارة. عند نشر بيئة أخرى طبّق المهاجرات قبل تشغيل النسخة الجديدة.

## SUPER_ADMIN

تُقدّم `MONEYTRACK_ADMIN_EMAIL` و`MONEYTRACK_ADMIN_PASSWORD` عبر مدير أسرار، واسم اختياري `MONEYTRACK_ADMIN_NAME`، ثم:

```bash
pnpm bootstrap:admin
```

الأداة تنشئ حساب المالك خادمياً مرة واحدة؛ إذا وجد مالك أو بريد موجود لا تستبدله ولا تعيد تعيين كلمة مروره. كلمة المرور تحفظ مجزأة بـscrypt. يجب تغيير المؤقتة من الإعدادات عند أول دخول؛ لا تسمح العمليات الحساسة قبل ذلك. احذف المتغيرات الثلاثة بعد التهيئة. لا تضعها في Git أو أوامر منشورة أو لقطات شاشة.

## SMTP — غير مُعد في هذا النشر

اختر مزود SMTP فعلياً ومُرسلاً موثقاً. من مدير الأسرار الخادمي اضبط أحد الخيارين:

- `SMTP_URL` (رابط SMTP محمي) و`SMTP_FROM`.
- أو `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_SECURE`, `SMTP_FROM`.

استخدم TLS، و`SMTP_SECURE=true` للمنفذ 465. للمنفذ 587 يستخدم المزود STARTTLS. لا تستخدم كلمة مرور الحساب البريدية العادية إذا كان المزود يتطلب App Password. اضبط `PUBLIC_APP_URL` على النطاق العام الفعلي، وليس المعاينة. أعد نشر/تشغيل الخادم بعد تعديل البيئة لأن transport يُهيأ مرة.

تحقق فعلياً من وصول رسالة التسجيل والتحقق وإعادة التعيين إلى بريد تملكه قبل وصف الإرسال بأنه جاهز. `/api/public/config` يعرض `emailConfigured` وفق وجود الإعداد، لا ضمان الوصول للصندوق. حتى الإعداد يعرض التسجيل العام واستعادة البريد رسالة عدم توفر خدمة، دون تجاوز التحقق أو توكنات وهمية. الدخول للحسابات الحالية ليس معتمداً على إرسال رسالة جديدة.

## القواعد الدورية والجدولة

القواعد تسجل دخلاً/مصروفاً محاسبياً داخلياً، وليست أوامر دفع بنكي. معالجة الاستحقاقات تحمي من تكرار نفس القاعدة/التاريخ، وتقيد الحساب النشط. عند فتح مساحة الحساب ينفذ catch-up للمستحقات؛ لا يعمل مؤقت متصفح في الخلفية.

للتشغيل بينما الحساب مغلق، ضع `CRON_SECRET` عشوائياً قوياً في البيئة الخادمية، واستخدم جدولة أصلية موثوقة تدعو `POST /api/cron/recurring` على الأصل الخلفي مع `Authorization: Bearer <CRON_SECRET>`. لا تضع المفتاح في URL أو Frontend أو Git. عند غيابه يعيد المسار 503، ولرمز غير صحيح 403. اختر معدل الجدولة وفق حدود مزودك، ثم تحقق من توليد الاستحقاق مرة واحدة. لا توجد جدولة خارجية مفعلة في هذه المرحلة ولا يُدعى أنها تعمل.

## Vercel والخادم
`vercel.json` ينشر التطبيق كدالة Serverless واحدة: `app.js` يصدّر تطبيق Express كـ`default export` (وهو ما يتعرف عليه Vercel تلقائياً)، و`buildCommand` يبني `dist/`، و`includeFiles` يضمّن `dist/` و`db/migrations/` و`js/` داخل حزمة الدالة. كل المسارات (صفحات، أصول ثابتة، API) يخدمها نفس تطبيق Express، لذلك حماية الجلسة على `/app` و`/admin` تعمل كما في التشغيل المحلي.
المتغيرات المطلوبة على Vercel: `DATABASE_URL`، و`PUBLIC_APP_URL` (النطاق العام الفعلي)، و`CRON_SECRET` عند تفعيل الجدولة، ومتغيرات SMTP. لا تضبط `MONEYTRACK_LOCAL_HTTP` في الإنتاج. الكوكيز `Secure` و`SameSite=None` وتُضبط بلا `Domain`، لذا تعمل على نطاق Vercel ونطاقك المخصص.
جدولة Vercel تدعم GET فقط، لذلك المسار `/api/cron/recurring` يقبل GET وPOST بنفس تحقق `Authorization: Bearer <CRON_SECRET>`، و`vercel.json` يسجله كل ساعة.
بعد النشر اختبر `/api/health` (200)، و`/api/public/config` (2.0.0)، ومجهولاً `/app` و`/admin` (توجيه للدخول)، ودخول USER/ADMIN في جلسات منفصلة. لا تصدر روابط المعاينة كاستضافة دائمة، ولا تخزن بيانات DB في البيئة الأمامية.

## النسخ والترحيل

بيانات LocalStorage القديمة تخص الأصل الذي كانت فيه. تظهر المراجعة فقط إذا وجدت نسخة صحيحة في نفس المتصفح؛ لا يمكن نقل LocalStorage بين نطاقين تلقائياً. صدّر JSON من النسخة القديمة إن كانت في نطاق آخر، ثم استعده بموافقة في الحساب المقصود. لا يُحذف الأصل القديم تلقائياً. أداة الاستيراد تمنع تكرار نفس الحمولة، وتستعمل معرفات متسقة للحساب وروابط الفئات/المعاملات.

تحتفظ الاستعادة بنسخة سابقة خادمية خاصة بالحساب. تنزيل JSON/CSV عملية حساسة تخص المالك؛ لا تُرفع النسخ إلى GitHub. مسح مساحة العمل يتطلب RESET ويحافظ على الهوية، بينما حذف الحساب يتطلب كلمة المرور الحالية وتأكيد DELETE ويحذف سجلاته التابعة بترتيب يحترم العلاقات.
